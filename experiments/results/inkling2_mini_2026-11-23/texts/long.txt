# HI2 for mixture-of-experts models

`hi2`'s MoE PTQ path calibrates, allocates and encodes routed experts into the
v3.2 flex format (`quant_method: rdna_hint_flex`). A per-expert projection is an
ordinary `model.layers.N.mlp.experts.E.{gate,up,down}_proj.hi2_*` tensor; the
current default instead groups experts into stacks per layer/projection group.
The tensor decode semantics are unchanged, but a native loader must support the
selected layout. Routers, norms, embeddings and heads stay dense.
This note records the implemented paths and the measured OLMoE-1B-7B-0924 PTQ
case, not general MoE QAD or runtime compatibility. Check the
[support matrix](getting-started.md#supported-inputs-and-evidence) first.

## How experts are handled

| Step | What the tool does | Why |
| --- | --- | --- |

The first expert views are compared bit for bit with the checkpoint tensors before calibration. | The module paths are the checkpoint names, so the dense machinery (hooks, resolver, writer) applies unchanged. """Global allocation: pick every row's ``(nbits, block)`` across the whole model.

Minimise ``sum_t s_t * sse_t / energy_t`` (relative weighted output error per
tensor, scaled by an optional sensitivity ``s_t``) subject to a model-wide
bits-per-weight target. For a multiplier ``lam`` every row independently picks the
candidate minimising ``cost + lam * bits``; ``lam`` is bisected to meet the target.
"""

import math
from dataclasses import dataclass

import torch

from .calibrate import TensorTable, candidate_row_bits

ROW_OVERHEAD_BITS = 48 + 2 + 1  # row constants + block-size flag + INT4 flag, per row


def row_overhead_bits(t: TensorTable) -> int:
    """Per-row overhead of spec 2.5 for the code widths the table allows: the INT4 flag
    is ``ceil(log2(#widths))`` bits (1 for INT2/INT4 as before, 2 with INT8 added)."""
    widths = len({nb for nb, _ in t.candidates})
    return ROW_OVERHEAD_BITS - 1 + max(1, math.ceil(math.log2(max(widths, 1))))


def _overhead(tables) -> int:
    return sum(
        row_overhead_bits(t) * t.shape[0]
        + t.shape[1] // 16
        + (16 * t.shape[1] if t.col_scale is not None else 0)  # smoothing vector
        for t in tables
    )

# HI2 quantization-aware distillation (QAD)

Tool-side extension of the HI2 v3.2 format (`format-spec.md`, section 13).
QAD changes which codes and block parameters are stored, never the format: a QAD
checkpoint is a normal `rdna_hint_flex` v3.2 checkpoint that `hi2 eval`,
`hi2 export-dense` and the fork's loader read unchanged.

## Quick start

QAD is **on by default** whenever calibration text is given:

```bash
cd .
# HF model -> QAD checkpoint (quality allocation, sensitivity probe, PTQ, then QAD)
python -m hi2 quantize <hf_model_dir> <out_dir> --calib calib.txt --max-error-ratio 6
# PTQ only
python -m hi2 quantize <hf_model_dir> <out_dir> --calib calib.txt --no-qad
# inspect inputs/settings and resource estimates; this is not a model execution
python -m hi2 quantize <hf_model_dir> <out_dir> --calib calib.txt --dry-run
# score it against the unquantized model on held-out text
python -m hi2 eval <hf_model_dir> <out_dir> --text heldout.txt --device cuda:0
# dense fp16 Hugging Face copy (llama.cpp requires a separate compatible GGUF conversion)
python -m hi2 export-dense <hf_model_dir> <out_dir> <dense_dir>
```

At the start the run logs that QAD is on and a rough estimate of layer-wise training
time on the chosen device. That estimate is not total runtime: final-KL, probing,
encoding and first-use compilation have separate costs ([operations.md](operations.md)).
A run without `--calib` (data-free) cannot distill: it logs a warning and writes a
PTQ checkpoint. `--no-qad` also selects PTQ only. `--max-error-ratio 6` is the
current default allocation target with QAD (see "Recommendation for the default
ratio"); this is a global error proxy, not a final-KLD guarantee.

def force_int8(
    tables: dict[str, TensorTable], sens: dict[str, float] | None, top: int
) -> tuple[dict[str, TensorTable], list[str]]:
    """Experiment rule: the ``top`` tensors with the highest probe sensitivity (among those
    with INT8 candidates) keep only their INT8 candidates, every other tensor loses them."""
    sens = sens or {}
    cand = [n for n, t in tables.items() if any(nb == 8 for nb, _ in t.candidates)]
    chosen = sorted(cand, key=lambda n: -sens.get(n, 1.0))[:top]
    out = {}
    for n, t in tables.items():
        if n in chosen:
            out[n] = restrict(t, lambda c: c[0] == 8)
        else:
            out[n] = restrict(t, lambda c: c[0] != 8)
    return out, chosen


def _costs(t: TensorTable, s: float):
    k = t.shape[1]
    cost = (s / max(t.energy, 1e-30)) * t.sse  # [C, R]

        [candidate_row_bits(nb, b, k) for nb, b in t.candidates], dtype=torch.float64
    )
    return cost.double(), bits


def _argmin0(v: torch.Tensor) -> torch.Tensor:
    """``v.argmin(0)`` (first index of the minimum, ``v`` without NaN) as C-1 vector
    compares: torch's strided dim-0 argmin is ~30x slower on CPU for ``[6, 10^5]``."""
    best = v[0].clone()
    idx = torch.zeros(v.shape[1], dtype=torch.int64)
    for c in range(1, v.shape[0]):
        m = v[c] < best
        best = torch.where(m, v[c], best)
        idx.masked_fill_(m, c)
    return idx

## What it does

The PTQ pipeline runs first, unchanged: phase 1 (statistics, smoothing vectors, rotation
flags, candidate tables, Hessians), the sensitivity probe, the allocation (quality mode
`--max-error-ratio` by default, or `--target-bpw`) and, per layer, the Hessian-aware
encode. QAD then trains the decoder layers one at a time, in order:

* **Inputs and targets.** Student input of layer `L` = the hidden states produced by the
  already quantized layers `0..L-1`; target = the unquantized layer `L` applied to the
  unquantized prefix's hidden states. Both live in RAM; one layer is on the GPU. Training
  against the teacher path asks each layer to absorb the error its prefix left.
* **Trainable, per Linear:** fp32 latent weights in the stored basis `H (W s)` and the
  per-block ladder bytes `(lo_u8, step_u8)` as continuous values. **Frozen:** every row's
  `(nbits, B)` from the PTQ allocation, the per-row fp16 constants
  `(lo_min, lo_scale, step_scale)`, the smoothing vector `s` and the Hadamard flags.

def calib_paths(path) -> list[Path]:
    """One path, a list of paths, or a comma-separated string of paths."""
    if isinstance(path, (list, tuple)):
        return [Path(p) for p in path]
    return [Path(p) for p in str(path).split(",") if p]


def read_calibration_text(path) -> str:
    """Text of one or several .txt / .jsonl (``text`` field) files, concatenated."""
    parts = []
    for p in calib_paths(path):
        if p.suffix == ".jsonl":
            parts.append(
                "\n\n".join(
                    json.loads(ln)["text"] for ln in p.read_text().splitlines() if ln
                )
            )
        else:
            parts.append(p.read_text())
    return "\n\n".join(parts)


def load_calibration_ids(path, tokenizer, samples: int, seq_len: int) -> torch.Tensor:

            f"({samples} x {seq_len}); lower --calib-samples or --seq-len"
        )
    return ids[:need].reshape(samples, seq_len)

                torch.cat([b, torch.zeros(pad, dtype=b.dtype)])
                .unsqueeze(1)
                .expand(c, r)
            )
            costs.append(cc)

            off += r

        self.bits = torch.cat(bits, 1).contiguous()

        """``(picks, picked bits per tensor, picked cost per tensor)``."""
        p = _argmin0(self.cost + lam * self.bits)
        pb = self.bits.gather(0, p[None])[0]
        pc = self.cost.gather(0, p[None])[0]
        picks, nbits, err = {}, [], []

            picks[name] = p[a:b].clone()
            nbits.append(pb[a:b].sum().item())
            err.append(pc[a:b].sum().item())
        return picks, nbits, err

def _attach_mmap_ngram(model, log=print) -> None:
    """Attach the PLE n-gram table from ``$HI2_NGRAM_MMAP`` instead of RAM.

    The table comes from a safetensors file as a zero-copy tensor, so 95 GiB costs page
    cache, not resident memory. The gather casts to the model dtype, which keeps an fp16
    run reading a bf16 file."""
    path = os.environ.get("HI2_NGRAM_MMAP")
    if not path:
        return
    from safetensors import safe_open

    parents = [m for m in model.modules() if hasattr(m, "ngram_embedding")]
    if not parents:
        log("ngram mmap: no module holds an ngram_embedding")
        return
    handle = safe_open(path, "pt")
    key = next(iter(handle.keys()))
    table = handle.get_tensor(key)
    dtype = next(model.parameters()).dtype
    _NGRAM_MMAP[path] = (table, handle, dtype)
    for parent in parents:
        parent.ngram_embedding = _MmapEmbedding(path)
    log(
        f"ngram mmap: {key} {tuple(table.shape)} {table.dtype} from {path} "
        f"(cast to {dtype} per gather)"
    )

### Names

A stack is `<pre>.<group>.hi2_<field>`. `<pre>` is the experts prefix of one layer
(`model.layers.L.mlp.experts`) and `<group>` is one of:

| group | parts, in row order | fork stage |
| --- | --- | --- |
| `gate_up` | `gate_proj`, `up_proj` | `w13` |
| `down` | `down_proj` | `w2` |
| `w13` (Mixtral names) | `w1`, `w3` | `w13` |
| `w2` (Mixtral names) | `w2` | `w2` |

A stack is recognised by its `hi2_part_off` array. A single HI2 tensor never has one.
`config.json` records the layout in `quantization_config`:
`"moe_layout": "stacked"` and `"moe_stacks": {"down": ["down_proj"], "gate_up":
["gate_proj", "up_proj"]}`, the groups used and their part order. `moe_layout` is
`per-expert` (and `moe_stacks` absent) after a restack back. Checkpoints written before
this change have no `moe_layout` key, which means per-expert.

### Arrays

`E` experts, `P` parts per expert (2 for `gate_up`, 1 for `down`), `K` input width
(hidden size for `gate_up`, intermediate size for `down`). Slice `j = e * P + p` is
part `p` of expert `e`, and `R` is the total row count. For OLMoE, `gate_up` has
E = 64, K = 2048 and R = 64 x 2 x 1024 = 131,072, and `down` has K = 1024 and
R = 64 x 2048 = 131,072.

| field | dtype | shape | content |
| --- | --- | --- | --- |
| `hi2_codes` | int32 | `[sum words]` | the slices' `codes`, concatenated in slice order |
| `hi2_code_off` | int32 | `[R + 1]`

### Invariants a loader can rely on

1. The seven row arrays form one valid flat container of `R` rows (spec 2.4).
   `code_off[0] = param_off[0] = 0`. `code_off[r+1] - code_off[r] = K * nbits_r / 32`
   and `param_off[r+1] - param_off[r] = K / block_r`. `code_off[R]` is the length of
   `hi2_codes` and `2 * param_off[R]` is the length of `hi2_blk_params`. The fork's
   `validate()` passes on them if `K` is taken as `had.shape[1] * 16`, not
   `had.numel() * 16`. All offsets fit int32; the writer keeps a group per expert
   rather than overflow.
2. `E = had.shape[0] = col_scale.shape[0]` and `part_off.numel() = E * P + 1`. Every
   expert and part of a stack has the same `K`.
3. `part_off[0] = 0` and `part_off[E * P] = R`. The parts of a group have equal row
   counts in every model the tool handles: OLMoE gate/up 1024 rows, down 2048 rows. The
   table states the counts, so a loader should read it, not assume them.
4. Row order is expert-major, part-minor. For `gate_up`, expert `e`'s rows
